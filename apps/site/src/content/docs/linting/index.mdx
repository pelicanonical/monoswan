monoswan checks your monorepo against rules and structures that you can configure.

Package selection follows a fixed pipeline: workspace patterns establish membership, the command
path narrows the selected packages, the root ignore configuration skips packages globally, and
rule-level ignores skip individual rules. Ignore configuration does not alter workspace
membership.

Run `monoswan lint .` to run in your current working directory.

Run `monoswan lint . --fix` to automatically fix any autofixable issues.

We recommend putting monoswan lint scripts in your package.json, and running these as part of any pre-commit hooks.

### Ignore packages

You may want to turn off monoswan rules for certain workspace packages. monoswan supports both
`paths` and `packages` ignore lists. Both ignore lists support glob patterns.

You can ignore certain packages for the entire lint operation. A matching path or package name is
not checked by any lint rule, but remains a discovered workspace package.

<Code code={ignorePackages} lang="ts" title="monoswan.config.ts" />

You can also ignore packages for specific rules. A matching path or package name skips the rule.

<Code code={ignoreRule} lang="ts" title="monoswan.config.ts" />

Path globs are matched against forward-slash paths relative to the workspace root containing the
nearest monoswan configuration. They do not start with `./`, so use `packages/legacy/**`, not
`./packages/legacy/**`. Package globs are matched separately against the package's `name`. A match
in either list is sufficient to skip the package.
